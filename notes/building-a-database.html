What it means to build a database from scratch.

Why NEXUSDB begins with disk pages, storage contracts, and testable durability—not a fancy dashboard.

When we say we are building a database from scratch, we mean implementing the engine that stores and retrieves information. Calling an existing database through an API is useful application development, but it does not teach the same systems trade-offs.

Our initial goal is a single-node relational database in Rust with custom page storage. SQL parsing and storage are separate subsystems so two contributors can build against a shared contract.

The engineering order matters: page I/O, durable records, SQL execution, then indexes and transaction logging. Correctness and restart tests must come before optimization.

This is a project note about architecture and goals, not a claim that the engine is already implemented.
